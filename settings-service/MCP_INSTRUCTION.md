SettingsService MCP — manages YAML configuration templates and the secrets they reference, grouped by `product_id`. BEFORE invoking any tool of this MCP, load the `how_to_use_settings` prompt: it explains the data model (products, templates, secrets, the Shared scope, levels, remote-datacenter variants), the placeholder syntax, the privacy rules (secret VALUES are never exposed by this MCP), and the recommended discover-then-read-then-write workflow. Two prompts are exposed: `how_to_use_settings` (no arguments — load it first) and `product_prompt` (argument `product_id` — loads a specific product's description and free-form context). Skip `how_to_use_settings` and you will misinterpret tool output (especially the missing-secret markers and the local/remote rendering rules). Authoring rule (full version inside `how_to_use_settings`): when writing or editing a template, default to `${secret_id}` placeholders for credentials, hostnames, URLs, per-environment identifiers, and anything a human might want to rotate without editing YAML — reuse existing secrets (check `list_secrets` with `include_shared: true` first) and create new ones via `create_secret` rather than hardcoding literal values.
